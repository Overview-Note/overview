# 长文档示例

本文用多级标题模拟一篇较长的文档，右侧「On this page」大纲会随标题层级展开，
用来验证 TOC 在大文档中的表现。

## 第一部分：背景

### 为什么需要知识库

散落在聊天记录、便签和邮件里的信息很难再次找到。一个本地优先的知识库，
既要让人快速记下想法，也要让几个月后的自己还能检索到它。

### 现有工具的取舍

| 方案 | 优点 | 代价 |
| --- | --- | --- |
| 文件夹 + 纯文本 | 简单、可移植 | 检索能力弱 |
| 在线协作文档 | 协作强 | 数据不在自己手里 |
| 本知识库 | 文件即真相 + 全文搜索 | 需要自己部署 |

#### 设计目标

1. 文件即真相，数据不被锁定；
2. 本地优先，可完全自托管；
3. 编辑体验接近现代文档工具。

## 第二部分：结构

### 笔记层级

#### 目录

真正的文件夹与子文件夹，路径即身份。

#### 标签

横切的分类维度，同一篇笔记可以属于多个主题。

### 双链与反链

用 `[[目标]]` 建立双向关联，反链面板回答「谁引用了我」。

## 第三部分：检索

### 倒排索引

更新笔记时同步写入 SQLite FTS5 索引，检索结果按相关度排序。

### 中文分词

中文使用 unigram + bigram，因此「并发模型」「发模」这类中缀都能命中。

## 第四部分：扩展

### REST 与 MCP

同一套 OpenAPI 规范同时驱动 REST 与 MCP 工具，接口保持同步。

### 静态导出

公开笔记可以导出为只读文档站，托管到任意静态服务器。

## 小结

这篇文档故意拉长层级，用来检验大纲、锚点与阅读体验。
